02 精準度

精準不是形容詞。
是一組可以查的版本號。

每一次計算都回報三個獨立的版本號——而且主動告訴你其中一個不歸我們管。

pyswisseph 套件2.10.3.2pip 安裝的 Python 套件
Swiss Ephemeris C 函式庫2.10.03函式庫自報，基於 JPL DE441
IANA 時區資料庫2026c由作業系統或 image 提供
不由本產品固定

前兩個數字格式相近，但不是同一個值——我們把這句話寫進每一份卷宗，因為搞混了會誤導。第三個更重要：時區資料庫更新後，同一組輸入可能換算出不同的 UTC。所以它的版本也印在你的卷宗裡。

已經對過外部基準的部分

  • 月相四相（朔、上弦、望、下弦）的事件時刻，已與 USNO Astronomical Applications API v4.0.1 的一分鐘精度資料交叉核對。
  • 臺北固定案例的太陽與月亮升起、過中天、落下，已與 USNO 單日表交叉核對；USNO 只顯示到分鐘，自動測試因此容許 2 分鐘誤差。
  • 黃赤交角逐次計算，取平交角加章動，不是寫死的常數——這張盤是 23°26′31.79″，平值 23°26′25.92″ 加章動 +5.870″。
  • 真高度與視高度分成兩欄；視高度另附折射模型與當時採用的氣壓、溫度假設，不會被合稱為「高度」。

邊界：下中天與極區狀態目前只有內部回歸測試，尚無第二套外部參照。真位置、J2000 與關閉章動三種模式在獨立參考管線的涵蓋範圍之外。「可執行」不等於「已獨立驗證」，兩者在〈驗證證據〉頁逐項分開列出。

03 出生時刻

只記得大約幾點？
那就別假裝知道。

這張盤如果只知道「下午兩點多」——
七顆星的落宮會在某一秒同時換宮。我們把那一秒找出來。

14:22:58 – 14:23:12翻面就發生在這 14 秒之間
7顆星的落宮同時改變
13.62°上升點在這一小時內的擺幅

做法是對整個小時取樣五個時刻，再用有界二分法把分類改變的位置夾出來：

14:00:00處女 24°46′40.7″
14:15:00處女 28°11′04.4″
14:30:00天秤 1°35′32.3″
14:45:00天秤 4°59′56.5″
14:59:59天秤 8°23′55.8″

月亮在這一小時內始終在摩羯，標為「取樣範圍內穩定」。求根方法字串 bounded_bisection_of_a_sampled_classification_change 也印在卷宗裡。

只知道日期呢？那就不給你上升點、中天、宮位與日夜盤——沒有時刻，那些東西不存在。我們改給你全日的位置範圍，並標出月亮可能跨星座。

邊界：五點取樣加有界二分，不是對整個連續小時的數學證明。五點都相同只能說「取樣範圍內穩定」。恆星、月相、地平事件與反照點在此模式下不取樣，未取樣的路徑會逐項列出。

04 口徑

兩個網站算出不同的上升星座。
通常兩邊都沒錯。

同一個時間、同一個地點。換一把尺，上升星座整個退一格。

回歸黃道 · 春分點為原點天秤 1°35′32″黃經 181.591957°
恆星黃道 · Fagan–Bradley處女 6°58′59″黃經 156.982954°

兩者相差 24°36′32″，就是這套歲差修正值。你可以自己把兩個黃經相減來核對。

可以換的口徑：黃道系統（回歸／四種恆星）、宮位制（整宮／Alcabitius／Regiomontanus／Placidus／不算宮位）、月亮位置（跟隨全域或單獨改用出生地站心）。換一項，哪些數字會動、動多少，當場看得見。

邊界：計算中心、位置模式與黃道框架目前固定為地心、視位置、當日框架，介面不提供切換；三者仍逐次印在卷宗裡。對帳需要知道「這次用了什麼」，那和「你可以改成什麼」是兩件事。

同一顆太陽，同一個時刻。這條驗證管道是刻意留的。

涵蓋七政、三王星、凱龍、平均與密切交點（含南交點）、Lilith 與 Priapus，以及 34 顆古典常引恆星。相位分兩層輸出：整宮配置層（純算術）與逐度層（角距離、距精確相位差、入相位方向）。四套相位集合、兩套具名容許度表，同樣沒有預設。

08 資安

資安跟隱私是兩件事。
隱私是我們不拿；資安是別人也拿不到。

瀏覽器收到的每一個安全標頭都是可以當場查的。
把開發者工具切到 Network，點任一個回應，就在 Headers 裡。

寫進程式裡的其他限制

  • 試算表公式注入防護：CSV 匯出時，凡是以 = + - @ 開頭而又不是合法數字的欄位，會被前置單引號。否則有人把公式塞進地名，你一開檔它就在你的電腦上執行。合法的 -2.5、1e-6 不受影響。
  • 請求上限：單次計算請求最大 16 KB，每個工作行程最多 32 個併發連線、其中計算類最多 4 個。超過就拒絕，不是排隊到資源耗盡。
  • 失敗優先：算不出來就明白說算不出來。極區的四分宮制回 422 並說明原因，不會偷偷換一個宮位制給你一個看起來正常的答案。
  • 供應鏈：沒有前端建置鏈、沒有 npm 執行期相依、沒有外部字型。你看到的每一個檔案都在公開原始碼裡，可以逐字比對。

邊界（這一段很重要）：我們沒有第三方安全認證，沒有專業滲透測試，也沒有漏洞獎金計畫。有的是寫進程式並由失敗優先測試守著的限制、多輪獨立 AI 紅隊與外部模型審查，以及一份誠實的「我們控制不了什麼」清單。這些都不等於專業滲透測試。完整的邊界、資料流與已知限制列在〈安全〉，那一頁是專門寫這件事的。

09 讀者

這個工具給誰用。

會問「你這個上升點是用什麼算的」的人

進階學習者與實務占星師。已經會排盤，在意臨界度數、宮頭、恆星與方法輸入值，現在得在兩三個工具之間手動核對。

要向學生或讀者交代設定的人

教師、作者、研究者。需要固定設定重現案例，需要可附錄的資料，需要一份說得出出處的講義素材。

不想讓 AI 自己猜天文數值的人

技術型使用者與 AI 工作流使用者。要 schema 穩定的 JSON、可讀的 Markdown，以及一份能重跑的請求。

目前不適合

剛開始學占星、想知道「我是什麼樣的人」的讀者。這裡不會告訴你任何一個數字代表什麼意思——那不在能力範圍內，也不會為了好賣而假裝在。
