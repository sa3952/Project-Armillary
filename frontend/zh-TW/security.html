安全 · SECURITY

安全頁通常在說服你。
這一頁在告訴你邊界在哪。

我們沒有第三方安全認證，沒有通過外部紅隊，沒有漏洞獎金計畫。

有的是：一組寫進程式、由失敗優先測試守著的限制；一台跑過驗證器與隱私探針的主機；以及一份誠實的「我們控制不了什麼」清單。

三者分開列。混在一起的安全頁，等於沒有安全頁。

不儲存什麼

應用程式裡沒有可以存出生資料的地方。不是「我們選擇不存」，是沒有那個元件：

沒有帳號資料庫、沒有命盤資料庫、沒有工作階段儲存、沒有請求快取、沒有出生資料快取、沒有背景佇列。

完整的資料流：

請求內容 → 請求範圍的資料模型 → 行程鎖底下的同步計算
         → 回應 ＋ 計算卷宗 → 你的瀏覽器記憶體
         → （只有你按下時）剪貼簿或下載檔案

這條路徑上沒有任何一步寫入磁碟。自動化守衛在計算請求期間攔截檔案寫入介面；只要請求路徑嘗試寫檔，測試就失敗。

唯一的資料庫是內建的地名目錄，以唯讀、不可變模式開啟。它不含帳號或出生資料，也不寫入搜尋字串。另有驗證器檢查它的雜湊、完整性、沒有寫入暫存附檔，以及唯讀執行策略。

這說的是沒有主動寫入，不是安全抹除。計算期間資料存在於記憶體中，之後由執行環境回收。我們不宣稱能從記憶體、swap 或當機傾印中安全抹除任何東西。

伺服器日誌裡有什麼

每完成一個請求輸出一行事件，只能有這十個欄位：

欄位允許的值
事件版本固定字串
事件名稱固定字串
請求 ID伺服器產生的 32 字元十六進位字串
路由固定分類，不是原始網址
方法GET／POST／HEAD／OPTIONS／其他
狀態碼100–599
耗時分組固定分組，不記精確耗時
請求大小分組固定區間，不記內容
結果成功／拒絕／錯誤／未知
錯誤代碼空值或四個固定字串之一

不會出現的東西：請求或回應內容、例外文字、堆疊追蹤、區域變數、查詢字串、完整網址、HTTP 標頭、cookie、authorization、呼叫端提供的請求 ID、IP 位址、User-Agent、referrer、出生時間、時區、地點、卷宗、計算軌跡、匯出內容。

這不是靠事後過濾做到的。事件由固定的建構函式產生，送出前再檢查一次欄位順序、版本、字彙與格式；把未清洗的資料直接送進輸出端會失敗關閉，該事件不會被輸出。

外部送來的請求 ID 標頭一律不採用。

錯誤訊息裡有什麼

未預期的例外一律回傳固定錯誤代碼與伺服器產生的請求 ID，不回顯例外原文。星曆函式庫的錯誤回傳固定代碼，不回顯原始錯誤文字（那可能含本機路徑）。

比較難處理的是回應已經開始送出之後才失敗——那時狀態碼已不能安全改寫。做法是：保留實際送出的狀態碼、把事件記為錯誤，並阻止原始例外進入框架的錯誤日誌。串流與背景工作的失敗路徑都有真實伺服器的反證測試。

日誌輸出端本身故障時，直接放棄該筆事件，不建立備援輸出端，也不影響你的回應。

不連出去

後端不含任何錯誤追蹤服務、應用效能監控、外部分析，也沒有對外的 HTTP 客戶端。原始碼守衛偵測到這類相依就直接失敗。

前端不載入外部字型、CDN 腳本、第三方 JavaScript 或遠端圖片。0 追蹤器、0 分析 cookie、0 第三方請求。

地名搜尋走同源請求，讀內建的唯讀目錄；不使用瀏覽器定位、不使用 IP 定位、不呼叫任何線上服務。

匯出檔名固定，不嵌入出生日期、時間、姓名或座標——檔案躺在下載資料夾裡，檔名本身不洩漏任何東西。

這項守衛的邊界：它是針對已審查名單上的名稱所設的迴歸阻擋，不是完整的資訊流分析，不是相依套件的遞移稽核，也不是執行期沙箱。名單外的新途徑仍需人工審查與探針測試。

瀏覽器端

不使用 localStorage、sessionStorage、IndexedDB、Cache Storage 或 beacon。敏感欄位使用 autocomplete="off"——這是提示，瀏覽器可以忽略。

清除結果
中止進行中的請求、使匯出文件失效、撤銷暫存網址、清除結果與錯誤，保留表單方便你修正後重算。
清除本頁敏感資料
另外清空所有出生與地點輸入、重設選項、清除網址參數，並在頁面隱藏時做盡力清除。

遲到的回應必須通過世代檢查——你清除之後，早先發出的請求不會把結果再貼回畫面。

這些控制不宣稱：JavaScript 引擎已安全覆寫記憶體；瀏覽器或作業系統不會保留當機還原、swap、螢幕截圖或擴充套件看得到的內容；已完成的剪貼簿寫入或下載可以撤回。

主機與部署

容器
沒有任何儲存掛載點；根檔案系統唯讀；只有一個小的記憶體暫存區且標為不可執行；丟棄全部系統權限；禁止提權；記憶體上限與 swap 上限相同（等於停用容器 swap）；行程數、檔案描述子、CPU 均設上限；內部網路。
反向代理
存取日誌關閉；不轉送原始 IP 與各種轉送標頭給應用程式；線上的 API 文件關閉。
作業系統
系統日誌短保留上限；停用 swap、當機傾印、自動備份與快照。
存取控制
少於 20 名受邀者，每人一組可撤銷、無識別性別名的憑證。憑證在代理層驗證，不在應用程式；主機只保存雜湊值。沒有帳號資料庫、沒有自助註冊、沒有 email 名單、沒有忘記密碼資料庫。
驗證方式
上列每一項在實際運行的主機上以驗證器與隱私探針逐項確認——設定檔存在不等於設定生效，我們用探針去證明它生效。

回應標頭要求搜尋引擎不索引、不追蹤、不封存。這是降低被收錄的措施，不是驗證機制，也不是「秘密網址」保護。

線上跑的是哪一版

後端會持續更新，線上執行的版本不必然等於公開程式庫的最新版本。

要確認你正在使用哪一版，請看卷宗裡的版本識別碼——不要從程式庫的最新提交推定。我們自己也不這樣推定。

相依套件與供應鏈

生產環境的相依套件以帶雜湊的鎖定檔固定；另有一份標準格式的軟體物料清單列出實際組成。第三方原始碼封存檔、雜湊、授權與上游位置另有清單記錄。

相依套件、星曆檔與時區資料庫三者性質不同，各有自己的更新節奏與驗證步驟，不共用一套流程。

星曆檔與恆星表的雜湊由測試直接驗證——有人替換了資料檔，測試會失敗。

這些是可查的程序與清單。它們不是供應鏈稽核，也不是對上游套件本身的安全保證。

我們控制不了什麼

卷宗裡的隱私聲明把下列各層列為未涵蓋，這不是疏漏，是刻意標示：

層為什麼
內容傳遞網路／應用防火牆目前架構沒有這些元件
供應商基礎設施由供應商決定
第三方遙測目前沒有；未來若新增須先經隱私審查
瀏覽器／作業系統／原生函式庫記憶體我們沒有能力觀察或抹除

不能從「某個元件不存在」推論出「因此安全」。

其他明確不在能力範圍內的：已取得你使用者權限的本機攻擊者；你安裝的瀏覽器擴充套件；你複製或下載之後的副本及其同步備份；供應商依法或依契約保存的紀錄；DNS、憑證簽發、網路轉送必然處理的連線 metadata。

測試證明了什麼、沒證明什麼

repository 內的測試是設計期的迴歸證據：

  • 不會在你每次計算時重新執行
  • 卷宗裡的證據欄位是指向測試的指標，不是「這次執行過並通過」的紀錄
  • 只證明它們各自陳述的範圍

隱私聲明的狀態標為「暫定，待外部審查」。在獨立紅隊完成之前不會改；即使通過，也不會自動延伸到未涵蓋的層。
